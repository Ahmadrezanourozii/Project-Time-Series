\section{Experiments \& Results}
\label{sec:exp}

Every experiment uses the five predefined subject-wise folds. A model is trained
on the 60 training subjects, its hyper-parameters and decision threshold are
chosen on the 20 validation subjects, and the 20 test subjects are predicted
once. Because the five test sets are disjoint, pooling them gives exactly one
prediction per subject and 10\,407 window predictions in total, so every subject
is tested once and never appears in two roles. We ran fifteen GPU sessions
covering four groups of experiments: the input representation, the architecture,
the foot configuration, and the evaluation protocol.

\subsection{Experiment 1: what the network is fed}
Table~\ref{tab:tokens} compares the input representations at subject level on
both feet. Raw signals were not merely weaker but unstable. On folds~1 and~4 the
validation AUC never left the neighbourhood of chance ($0.53$ and $0.54$) while
folds~2, 3 and~5 exceeded $0.92$ with the same code and hyper-parameter grid.
Longer windows (30\,s, 60\,s), restarts with fresh seeds and a larger encoder
all failed to repair it. Amplitude-statistic tokens fixed the problem outright:
the weakest fold rose to $0.75$ validation AUC and accuracy improved by seven
points. Stride-cycle tokens were the weakest input on their own, and fusing them
with the amplitude tokens did not beat the amplitude tokens alone, even though
the two families are complementary at subject level in a Random Forest (AUC
$0.79$, $0.83$ and $0.86$ for stride, amplitude and both).

\subsection{Experiment 2: architecture}
With the input fixed, encoder capacity was the factor that moved accuracy:
enlarging the encoder from $d_{\text{model}}=128$, $L=4$ to
$d_{\text{model}}=256$, $L=6$ took subject-level accuracy from 72\,\% to 80\,\%.
The bidirectional block did not. At matched size the causal and bidirectional
encoders reach the same calibrated accuracy, and the causal one is slightly
better both at the fixed threshold and in AUC ($0.87$ versus $0.82$). Since a
bidirectional block doubles the mixer parameters, size and directionality are
partly confounded in the larger model, and we make no claim of a benefit from
processing the window in both directions.

Training converged very early: the best epoch was typically between one and four
out of thirty, which is a symptom of the small effective sample rather than of
the schedule. We therefore kept dropout at $0.1$--$0.3$, used a three-epoch
warm-up with cosine decay, and averaged three seeds. Stronger regularisation
(dropout $0.5$) did not help, and neither did five seeds instead of three or
late fusion across token families, which scored 0.72--0.77 and so stayed below
the best single model.

\subsection{Experiment 3: selecting a configuration without using the test set}
\label{ssec:selection}
Forty-five configurations were trained in total. Choosing among them by pooled
test accuracy would leak the test set into the model definition, even though
each individual run keeps train, validation and test apart. We therefore ranked
all configurations by their mean validation ROC-AUC across the five folds, a
quantity that never sees test data, and report the configuration that wins on
that criterion.

The two criteria agree on the important choice and disagree on the details.
Amplitude-statistic tokens win under both, so the finding of
Section~\ref{sec:exp} stands. The specific window length and encoder size do
differ: validation prefers 60\,s windows with the base encoder, whereas pooled
test accuracy prefers 30\,s windows with the large encoder. The gap between the
two is about three accuracy points, and that gap is the amount of optimism a
test-based search would have introduced. Table~\ref{tab:main} reports the
validation-selected configuration.

\subsection{Experiment 4: comparison with the baselines}

identical evaluation code and the same subject-level aggregation, and
Figure~\ref{fig:results}(a) shows the same comparison per foot configuration.
Sensitivity exceeds specificity for the Mamba model, which is the error profile
a screening tool should prefer: it misses few patients at the price of some
false alarms. Figure~\ref{fig:confusion} gives the confusion matrices.

\subsection{Experiment 5: the evaluation protocol}
\label{ssec:protocols}
To measure the influence of the split unit we repeated the evaluation with
windows -- not subjects -- assigned at random to the 60/20/20 splits, leaving
the data, features, models, metrics and code untouched
(Figure~\ref{fig:protocols}). Table~\ref{tab:protocols} contrasts the two for
the classical baselines, which are cheap to retrain. Accuracy rises by twenty
points or more and the Random Forest reaches 98\,\%. A per-subject decision has
no meaning under this protocol, since a subject's windows are spread across
training and test, so only window-level numbers can be quoted. These numbers
measure how well a model recognises individuals it has already seen, not whether
it detects Parkinson's disease in a new patient, and we give them purely as a
reference point for reading the literature.
